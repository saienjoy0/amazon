# Global SSD Research

## Purpose
海外のAmazon Sub-Same-Day (SSD) を横断し、SSDに普遍的な特徴と国別差を分けて整理する。最終目的は、Amazon JapanでSSD配属を希望することが、将来的なProgram Manager / Corporate / Ops Excellence / Central Operationsへのキャリア形成に有利か判断すること。

## Executive summary
現時点の調査では、SSDは単なる小型FCではなく、顧客近傍に在庫を置き、Fulfillmentと配送を近接・統合し、Same-Day / Overnight等の短い時間窓を何度も回す高速オペレーション網として各国で共通している。

複数国で共通して確認できた特徴は以下。

1. 顧客近傍に在庫を配置して配送距離・handoffを削減
2. FCとDSの境界が薄く、Inbound / Pick / Pack / Outbound / Dispatchを広く扱う
3. Site Operationsの隣にLaunch / Ops Excellence / Central Ops / Planning / Program Management組織が存在
4. 新規拠点・新機能展開が多く、Launch・標準化・Process Improvement経験を作りやすい
5. Data / Metrics / Capacity / Labor / Throughput / Quality / Safety / Costを横断して管理

一方で、SSD AMがFC/DS AMより高確率でProgram Managerへ移ることはまだ定量的に証明できていない。

## 2. Universal SSD operating model

### 2.1 Customer proximity
SSDは商品を顧客に近い拠点へ配置し、従来の大型FC→Sort→DS→Customerのような複数handoffを圧縮する方向に設計されている。

### 2.2 FC + DS integration
複数国の求人・社員情報では、SSD Siteで以下を同一拠点または同一Operations組織が広く管理する例が確認できる。

- Inbound
- ICQA / Inventory
- Pick
- Pack
- Outbound
- Dispatch / Delivery preparation
- Same-Day / Overnight cycles

通常FCで一工程を深く持つAMより、End-to-Endの理解を作りやすい可能性が高い。

### 2.3 Broad AM scope
SSD Area Managerに共通する管理対象として以下が頻出。

- Labor planning
- Staffing
- Workflow balancing
- Throughput
- Labor utilization
- Quality / defect
- Safety
- Cost
- Cycle readiness
- Real-time operational adjustment

一方、Support teamが通常FCより薄いSiteでは、AMが広範囲を持つため「何でも屋」化するリスクもある。

## 3. Why SSD may be career-positive

### 3.1 Launch opportunities
SSDは各国で拡張期にあり、新拠点・新都市・新配送WindowのLaunchが多い。

Launch経験から得やすいもの：

- Site launch planning
- SOP / standardization
- Cross-functional coordination
- Capacity planning
- Process design
- Tech deployment
- KPI stabilization
- Post-launch improvement

これはProgram Manager求人で要求される経験と接続しやすい。

### 3.2 Ops Excellence adjacency
米国・日本等ではSSD Field Operationsの横にOps Excellence / Ops Integration / Launch & Expansion / Central Operations等の組織が存在する。

想定されるキャリア接続：

SSD AM
→ Site-level Process Improvement
→ Ops Excellence / Central Ops / Launch
→ Program Manager
→ Senior Program Manager / Network PM

### 3.3 Network-level work
SSDの上位PM組織では以下の仕事が確認される。

- Network Planning
- Capacity
- Site selection
- ROI / budget
- Launch
- Network design
- Standardization
- Technology project
- Cross-team coordination
- Pilot → launch → network-wide scale

Site OpsからNetwork PMへ伸ばしやすい構造がある。

## 4. Country observations

### United States
- SSD Area ManagerはInbound / Pick / Pack / Outbound等を横断してShift executionを担う例がある
- SSD Expansion / Ops Integration / Central Operations Strategy / Delivery Ops Tech等のCorporate組織が存在
- Pilot → Site Launch → Network-wide scaleというProgram Management機能が明確
- 社員コミュニティでは「半分FC・半分DS」「通常FCよりSupportが少ない」等の証言あり

### Canada
- Same-Day NetworkをToronto, Ottawa, Hamilton, Vancouver, Calgary, Edmonton, Montreal等へ拡張
- 新規Launchに関わる社員が複数都市を跨いで経験を積んでいる
- 顧客近傍にFulfillment capacityを置く思想が明確

### United Kingdom
- SSDは保管・Fulfillment・最終配送を同一施設に近づけるモデル
- Birmingham等から拡張し、Coventry / Ipswich等へ展開
- OpsだけでなくIT / Software / Integration / End-to-End testingもLaunchに関与

### India
- SSD単体よりSpeed ProgramsとしてFresh / SSD / Amazon Now / Quick Commerce等と近い組織で扱われる傾向
- Central Operations / Supply Chain / Process Improvement / Lean / Cost / Quality等との接続が強い
- SSD経験がQuick Commerce側へ転用される例がある

### Japan
- SSD / SSD Grocery / Quick CommerceをSpeed Services系として拡張
- SSD Ops Excellenceの採用・組織形成が進行
- Field Ops / Ops Excellence / Program Managementの隣接構造が確認できる
- 日本での実績蓄積は米国より浅く、転換率の定量評価はまだ困難

### Brazil
- SSD立ち上げ初期市場として参考になる
- AMがIB / ICQA / OB / Delivery preparationを横断する求人あり
- 拡張初期ほどLaunch / Standardization / Central Controlの機会が生まれやすい可能性

## 6. FC vs DS vs SSD — current hypothesis

| Dimension | FC | DS / AMZL | SSD |
|---|---|---|---|
| Large-scale people management | High | High | Medium-High |
| Depth in one process | Very High | Medium | Medium |
| End-to-end understanding | Low-Medium | Medium-High | Very High |
| Inbound-to-last-mile connection | Low | Medium | Very High |
| Launch exposure | Medium | High | Very High |
| Data / process improvement | High | Medium-High | High |
| Central / network adjacency | High | High | High |
| PM bridge potential | Medium-High | High | High (hypothesis) |
| Historical career evidence | Very High | High | Still limited |
| Growth / expansion potential | Medium | High | Very High |

Important: PM bridge potential is a qualitative assessment based on org structure and cases, not a measured transition rate.

---

## 7. Work-life balance / risk

SSD should NOT be treated as automatically easier than FC / DS.

Observed risks:

- Long shifts
- Night / overnight cycles
- Lean support structure
- Broader manager responsibility
- Launch-period instability
- High-speed execution pressure

Some employees describe SSD as balanced; others describe 4x12h schedules and broad responsibilities. WLB appears highly site-, leader-, country-, and launch-phase-dependent.

## 8. Implication for Japan career strategy

SSD配属の価値は「楽そう」「新しい施設」という点ではなく、以下の組織隣接性にある。

Field Operations
→ Process Improvement
→ Ops Excellence
→ Central Operations
→ Launch / Expansion

Amazon JapanでSSDに入る場合、単に良いAMになるだけでは弱い。

### Year 1

- Safety / Quality / Cost / Delivery / ProductivityのKPI実績
- PA / AA People Management

### Year 1–2

- Data / Metrics / Automation
- Standardization
- Cross-functional Project

### Year 2+
- Network / Launch / Ops Excellence / Central Ops ProjectへScope拡張
- Internal job posting開始
- PMに必要なSTAR実績を定量化

### Year 2–4
候補：
- Ops Excellence
- Central Operations
- Launch & Expansion
- Project Manager
- Transportation / Planning
- Program Manager

## 9. What is proven vs not proven

### High confidence
- SSDは顧客近傍の高速配送Network
- FCとDSの機能境界が薄い
- End-to-End scopeが広い
- Launch / Process Improvement / Central / PM組織が複数国で存在
- SSD Ops経験からNetwork PMへ進む実例が存在

### Medium confidence
- SSDは通常FCよりLaunch / 横断Project機会が多い
- SSDはPMに必要なCross-functional経験を作りやすい
- 成長市場では若手でもScope拡大機会が生まれやすい

### Not yet proven
- SSD AMのPM転換率がFC / DSより高い
- SSD AMの昇進速度がFC / DSより速い
- SSDのWLBがFC / DSより良い
- Japan SSDで同じキャリアパターンが再現される確率

## Current decision view
現時点ではSSDは、将来Program Manager / Central Ops / Ops Excellenceを狙う人にとって有力な配属候補。ただし「SSDだから自動的にPMへ行ける」とは言えない。

最も合理的な戦略は、SSDの広いEnd-to-End Scopeと拡張期のLaunch機会を利用して、2年目前後からSite Opsを超えるNetwork-level実績を作り、横移動すること。
